# One native world, iterative settlement

Implemented 30 October 2026. The live path builds one connected working scene
and settles its existing carriers, ports and error relations in place. It does
not rebuild a scene, rerun classification, serialize JSON or retain earlier
rounds inside the numeric loop. The inspection path remains available.

## Execution and scope

One bounded source-local admission phase performs joint repair, source interval
splitting, shape construction and supported connection capture. Native affine
error laws then address the same ports on every numeric round. Parameter changes
enter through `Carrier.ReceiveTogether`; current receipts preserve accepted,
blocked, deferred, quantum and candidate-rejected participation. The original
source remains unchanged. Live working sites own distinct mutable tick references
and explicit publication maps from the native machines.

Only the initial and final views are retained. Current accounting is selected
into the final binary checkpoint without its detailed request/preview forest;
open slots mark that omission. This is not a new packed opcode language or a
handwritten decimal solver renamed Gojo. The existing native construction and
response machinery performs the calculation. Host scheduling, initial proposals
and the learned local classifiers remain outside the native kernel.

This first path holds its admitted topology and construction choices fixed.
Adaptive recapture/release and further joint replacement remain in inspection
mode. Scalar trend memory persists across the live rounds. Therefore live output
is not required to equal an adaptive run. Exact response parity is instead tested
between equivalent fixed scenes with history enabled and disabled.

## Verification

* 5,556 Gojo tests, including 149 ConstructionMachines tests.
* 173 QuickDraw solution tests and 258 Python tests passed.
* The complete current machine surface remains bounded over 200 forced moving
  iterations, with one isolated preview-world import instead of one per response.
* Church tests cover stable root/carrier/port/site identity, fixed-law response
  parity, independently owned equal sites, exact source preservation, curved
  handle publication and bounded current witnesses during continued movement.
* Rejected candidates do not mutate the live machine; stale requests remain
  rejected. Captured scratch output cannot be changed by a later preview.
* Independent pilot restoration reproduced 19 source edges, 41 shape points
  and 151 error reads exactly; all 60 retained actuator outcomes balance exactly.
* A fresh one-church full conversion saved all stages with zero errors.
* Live and earlier audit reviews passed browser navigation/toggle checks with no
  script errors or network requests. Sparse initial/final keyboard navigation
  works. Desktop Release startup and folder viewing passed.

The current checkpoint restores local machines and error laws. It does not
recreate the whole live scene scheduler/publication bridge or resume adaptive
construction search. History-free also does not mean allocation-free: current
equation witnesses and admissibility reads are still transient work.
